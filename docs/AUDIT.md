## 長所（Strengths）50

### 誠実性アーキテクチャ
1. 全関節が `observed|predicted` の state を持ち、推測を観測と誤魔化さない
2. 全関節に `confidence` 0–1 が付く
3. 全関節に `basis`（出典文字列）が付き「なぜその値か」が追える
4. 推定由来の出力は `state:"estimated"` 等で格付けされる設計慣習
5. `assumption` フィールドで暗黙の仮定を文章化して開示する慣習
6. `coverage` ブロックで文書全体の証拠依存度が定量化される
7. `audit` で誠実性リント（証拠薄/出典欠落/帳簿陳腐化を警告コード化）
8. `occlusion` が「なぜ見えないか」を occluded/truncated/absent に分類
9. `consistency` で骨格の解剖学的健全性を監査できる
10. `rom` で関節可動域の生理学的破れを検出できる

### 知識基盤
11. `slice.knowledge/v1` スキーマ＋`validate()` による形式検証
12. `KnowledgeStore` のファイルベース保存（id付き・gitで版管理可能）
13. `diff` でドキュメント間の差分監査（移動/降格/帳簿不整合）
14. `dedup` で近重複解析を検出（トルソ正規化・解像度不変）
15. `audit`+`validate`+`dedup`+`diff` が揃ったデータセットQA層
16. `dataset` でCSV/JSONL一括エクスポート（state/basis保持）
17. `bundle` でzip梱包（manifest付き・両側validate）
18. `stats` で関節観測率の集約＝推定器の死角が見える
19. OpenPose互換 `keypoints_2d` エクスポートを内蔵
20. `coco` 形式 vフラグが observed/predicted/missing に自然対応

### 推定・人体モデル
21. stdlibオンリーで動くヒューリスティック推定器（依存ゼロ）
22. `anatomy` の統計的人体プライア（adult/childモデル）
23. `predict` が中間関節を親子チェーンで補間（幾何整合）
24. `norm` の座標正規化（crop/resizeに骨格を追従）
25. `mask` 前景分離が切り出し・可視化・coverageに再利用可能
26. `autocrop`/`crop`/`pad` の前処理プリミティブ（正直なclamp）
27. `scale` で実寸cm推定（頭長プライア・estimated明記）
28. `horizon` でカメラロール/地面のシーン幾何を推定
29. `framepos` で構図（headroom/三分割）を解析
30. `style` でreal/anime/sketchの画像種別を推定

### 身体理解の意味層
31. `classify` で立つ/座る/歩く等の姿勢分類
32. `gesture`/`contact`/`handpos` で意味的ジェスチャ検出（observedのみ証拠）
33. `balance` で重心×支持多角形の静的安定判定
34. `gait` で脚ごとの stance/swing 位相キュー
35. `dominance` で荷重優位側を推定
36. `plumb`/`spine`/`axis`/`symmetry` で姿勢品質を連続計測
37. `limbs` で四肢チェーン長プロファイル＋左右差
38. `mass` で体重推定（仮定チェーン全開示）
39. `dynamics` で単フレームの運動含意を implied 格付けで推定
40. `describe` で人間可読の姿勢説明文を生成（NLG）

### 数値・変換・検証ツール
41. `ik` 2ボーンIK／`retarget` 体格間ポーズ転写
42. `motion`/`smooth` の時系列プリミティブ
43. `signature`/`compare`/`reid` の照合・再同定層
44. `oks`/`evaluate` の評価メトリクス＋正解フィクスチャ
45. `mirror`/`mutate` で対称性・ロバストネス検証
46. `render`/`svg`/`ascii`/`sheet`/`heatmap`/`paf` の6描画系
47. `contour`/`topology`/`distfield` の形状解析層
48. `rig`/`bvh`/`gltf` でアニメーションツールチェーンへ橋渡し
49. `lift` の正直な pseudo-3D（根拠無き正面=全z0）

## 短所（Weaknesses）50

### 入力側の限界
1. **JPEG/WebPはPillow任意依存** — stdlib純粋系ではPNG/BMPのみ（実写の主流形式）
2. **複数人を検出しない** — `_largest_component` が最大成分だけを見る
3. **背景均一色前提** — 複雑背景・グラデ背景で前景分離が破綻する
4. **全身が見える前提** — 半身/膝上クロップで関節推定が大きく劣化
5. **downscale(≤512px)前提** — 大画像では小関節がつぶれる
6. **背面・45度斜め向きの扱いが弱い** — 向き推定は front/left/right の3値
7. **実写での検証実績なし** — 全テストが synthetic fixture
8. **アニメ/線画での輪郭前提が実写系シルエット抽出と同じ** — 白抜き線画は中身が背景色
9. **暗い被写体のcutoutバグ** — `mask.cutout` が透明**黒**で埋め、再推定で暗色人物が消失（本監査で修正）
10. **低コントラスト（人物≈背景色）で静かに空Skeleton** — 失敗理由の返却が薄い

### 推定器の構造的限界
11. **学習モデルなし** — ヒューリスティックのみ。実写でMediaPipe等に精度が劣る
12. **19関節のみ** — 指・手首形状・顔 landmarks なし
13. **手・足が単点** — つま先方向・手の向きが取れない
14. **3Dは pseudo-lift のみ** — 真の深度・SMPLフィッティング未実装
15. **時系列にIDトラッキングなし** — smoothはあるが「誰が誰か」の連続性がない
16. **confidenceが校正されていない** — ヒューリスティック割当で実確率と未対応
17. **`_background` が端点サンプリング** — 人物がフレーム端に触れると背景推定が狂う
18. **背景推定がアルファ無視** — 透過画素のRGBを背景色として読む（cutoutバグの根因）
19. **向き推定は頭頂偏移ベース** — 髪型・帽子で誤判定し得る
20. **性別・年齢の構造推定は廃止/限定的** — gender_cue系は未統合

### スキーマ・API
21. **スキーマが v1 固定** — estimated/implied/out_of_frame等新state語彙がスキーマに未登録
22. **拡張フィールドの仕組みなし** — 73モジュールの出力を文書に載せる標準的置き場がない
23. **`basis` が自由英語文字列** — 機械可読な provenance enum/vocab ではない
24. **prediction.observed 帳簿は生成時点の写し** — 後編集で陳腐化する（auditで検出可能だが仕組みは別）
25. **skeleton.frame が width/height のみ** — 色空間・DPI・向き(Exif)を保持しない
26. **画像を保持しない** (`image_retained:false`) — 事後の再検証には元画像が別途必要
27. **id が `k_`+12hex** — 時系列ソート可能な情報を持たない
28. **RESTに認証・レート制限なし** — ローカル前提なら妥当だが127.0.0.1以外に置けない
29. **RESTのanalyzeは同期処理** — 大画像でワーカーを占有
30. **CORS設定なし** — ブラウザ別オリジンからの利用に制約

### 統合・運用
31. **CI未設定** — 322テストがローカル実行依存、回帰は人の記憶頼み
32. **pipelineが統合するのは少数モジュールのみ** — 追加73モジュールの大半は手動import前提
33. **モジュール間のAPI非統一** — dict返し vs Skeleton返し vs Bitmap返しが混在
34. **`_mask` 等プライベートAPIへの公開依存** — mask/contour/topologyが内部メソッドを呼ぶ
35. **KnowledgeStoreがO(n)全読み** — `list()` が全JSONを毎回parse（索引なし）
36. **storeの書き込みが非原子的** — tmp+rename がなく中途ファイルが残り得る
37. **analyze CLIが1画像ずつ** — バッチ解析の標準経路なし
38. **viewerが貼り付け式** — ブラウザからのstore直接参照に弱い
39. **ログ・進捗出力なし** — 大バッチで何が起きているか見えない
40. **エラーが英語のみ・例外ベース** — ユーザ向け診断メッセージ層がない

### 品質・ドキュメント
41. **評価がsynthetic基準** — 実データの ground truth がrepoに無い
42. **ベンチマークなし** — 推定器の精度/速度の数値目標が存在しない
43. **Pure Pythonの速度限界** — 全画素走査が大画像・バッチで遅い
44. **日本語ドキュメントが薄い** — README/docstringは英語主体
45. **ドキュメントとコードの乖離リスク** — 73モジュールの使い方がREADMEに未反映
46. **テスト名の体系がモジュール名依存** — 横断的な契約テスト（全モジュールがstate語彙を守るか）は未整備
47. **バージョン番号が知識スキーマのみ** — パッケージ自体のバージョニング方針が曖昧
48. **依存ゼロは諸刃** — Pillowがあると機能が変わる（decode経路が環境差分を生む）
49. **色覚多様性への配慮が薄い** — renderは青/橙（比較的良いが線種情報も予測/観測で必要）
50. **完成度指標が自己申告** — Phase 2→3の移行基準が定量的でない

## 改善点（Improvements）— 第一原理＋ソクラテス問答

### 第一原理からの逆算
北極星: 「人体を理解するAI」。理解とは = **観測した事実・推定した構造・
なぜそう判断したかの出典、を分離して知識化する**こと。
現在の最大のギャップは「入力の現実世界との接続」と「知識の統合」。

### ソクラテス問答からの優先度
- 「精度が低いのは誰のせいか？」→ ヒューリスティック単一経路。
  **P0: 入力層の現実対応**（JPEG/複雑背景/複数人/部分人体）
- 「知識があるのに使えないのはなぜ？」→ 統合経路が薄い。
  **P1: pipeline統合とスキーマv1.1**
- 「信用できると誰が言うのか？」→ syntheticのみでは不十分。
  **P1: CI + 実画像フィクスチャ + ベンチマーク**

### P0 — 入力の現実対応
1. **複数人検出**: `_largest_component` の top-K 成分を複数Skeletonとして返す経路（`estimate_multi`）
2. **部分人体モード**: 検出された人体領域のカバレッジから「全身写っていない」を診断し、
   範囲外関節を out_of_frame として報告（occlusionモジュールを統合）
3. **複雑背景の耐性**: 背景推定を端点サンプリング→複数点投票+透過画素除外に
4. **暗色cutout修正**: `mask.cutout` が元RGBを保持するよう修正（本PRで実施）
5. **失敗診断**: 空Skeleton時に理由コード（no_foreground/too_small/low_contrast）を返す

### P1 — 知識の統合と信頼性
6. **CI導入**: GitHub Actionsで `unittest discover` をPRごとに実行
7. **スキーマ v1.1**: `state` enum に estimated/implied/out_of_frame/unknown を正式登録
8. **拡張スロット**: `analysis:` フィールドで新モジュール出力を文書に格納する標準場所
9. **pipeline統合**: analyze 出力に coverage+audit+warnings を標準添付
10. **store索引**: `list()` を manifest キャッシュ化（O(1) read）
11. **原子的書き込み**: `save()` を tmp+os.replace に
12. **実画像フィクスチャ**: 実写/イラスト数枚+手動正解関節の回帰テスト

### P2 — 精度の底上げ
13. **ベンチマーク**: 推定時間とOKSを計測する gate スクリプト
14. **背景推定の堅牢化**: 透過画素除外+複数候補投票（#9の根因）
15. **指先・顔向きの拡張 landmark**（v2関節セット検討）
16. **バッチCLI**: `slice analyze dir/` で store 一括投入
17. **REST認証オプション**: トークンヘッダ1本で外部公開可能に

### P3 — Phase 3 布石
18. **真の3D**: liftの先、SMPLパラメータ近似の研究対応表（RESEARCH.mdに追加）
19. **temporal ID**: smooth/motion の先に「同一人物の連続」reid統合
20. **rig→retarget→bvh の動作検証デモ**

### P4 — 仕上げ
21. **READMEのモジュール一覧**と日本語ガイド
22. **basis語彙のenum化**（"symmetry"/"prior"/"interp" 等の語彙表）
23. **色覚対応**: renderの状態表現を色+線種の二重化
24. **完成度指標の定量化**: Phase基準をテスト可能な形式で docs に
